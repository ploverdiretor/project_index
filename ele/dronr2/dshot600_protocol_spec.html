DShot600 プロトコル詳細解説（設計者向け）

DShotは、フライトコントローラー（FC）とESC（Electronic Speed Controller）間で用いられる、単方向（基本形）の非同期シリアル・ソースシンク型デジタル通信プロトコルです。

1. 物理層と信号符号化（Encoding）

DShotは、一般的なUARTのようなスタート/ストップビット形式ではなく、1波形（1ビット）のパルス幅（デューティ比）で「0」と「1」を表現するPWMパルス幅符号化（TDR: Time-Domain Representation）を採用しています。これにより、クロック同期線を省きながらも高い同期性を維持しています。

タイムスロット（1ビットの構造）

1ビットの送信時間を T としたとき、信号の立ち上がり（Rising Edge）から次の立ち上がりまでを1周期とします。

  • ビット「0」: 周期の 37.5% の期間 HIGH を維持し、残りの 62.5% は LOW。
  • ビット「1」: 周期の 75.0% の期間 HIGH を維持し、残りの 25.0% は LOW。
ビット「0」:
|--37.5%--|-------62.5%-------|
[=========]___________________| (計 1.0T)

ビット「1」:
|-------75.0%-------|---25.0%-|
[===================]_________| (計 1.0T)

DShot600の具体的なタイミング規定

DShot600のビットレートは 600 kbps です。したがって、1ビットあたりの総時間 T は 1 / 600,000 ≈ 1.67 μs となります。

パラメータ 規定値（理論値） 許容誤差範囲
1ビット総時間 (T) 1,667 ns ±10% 程度（ESCの内部RC発振に依存）
「0」のHIGH時間 (T₀_H) 625 ns T × 0.375
「1」のHIGH時間 (T₁_H) 1,250 ns T × 0.750

2. フレーム構造（Frame Structure）

1回の通信（1フレーム）は計 16ビットの固定長データパケットで構成されます。MSB（最上位ビット）から順に送信されます。

MSB                                                      LSB
+-----------------------------------+----------+-----------+
|      Throttle Value (11-bit)      | Telemetry| CRC (4-bit) |
|           [15 : 5]                |   (1b)   |  [3 : 0]  |
+-----------------------------------+----------+-----------+
  • ① Throttle Value（11ビット: ビット15〜5）： モーターの出力命令またはコマンドを指定します。レンジ値は 0 〜 2047 です。
    • 0: ディスアーム（モーター停止・初期状態）
    • 1 〜 47: コマンドモード（ESCのBuzzer鳴動、回転方向反転など）
    • 48 〜 2047: スロットル出力値（48 がモーター回転の最小値、2047 が最大出力）
  • ② Telemetry（1ビット: ビット4）： ESCに対して、テレメトリデータの返送を要求するフラグです。1 の場合、ESCは指定された方法でFCへステータス（回転数、温度など）を返送します。
  • ③ CRC（4ビット: ビット3〜0）： ニブル単位（4ビット）のチェックサムです。データの整合性を検証します。計算対象は上位12ビットです。

CRC計算アルゴリズム（C言語表現）

uint8_t packet_telemetry = (throttle << 1) | telemetry; // 12bitデータ
uint8_t crc = (packet_telemetry ^ (packet_telemetry >> 4) ^ (packet_telemetry >> 8)) & 0x0F;

3. タイミング特性とインターフェース要件

1フレーム（16ビット）の送信にかかる純粋な時間は 16 × 1.667 μs = 26.67 μs です。

ESCのデコーダが「フレームの終わり」を認識し、受信データをラッチしてパルス計測カウンタをリセットするために、フレーム間には必ず最小 30 μs 以上（推奨 40 μs 以上）の LOW 状態（リセットタイム）を確保する必要があります。

このため、DShot600における実質的な最短最大フレームレート（理論上限値）は、約 1 / (26.67 μs + 30 μs) ≈ 17.6 kHz となり、8kHzや4kHzのPIDループに完全に同期（同期駆動）可能な設計になっています。

4. マイコン側（MCU）の実装戦略

FC側（STM32など）で正確なパルス幅をCPUの介在なしに生成するため、通常は DMA（Direct Memory Access）付きのタイマー（TIM） が使用されます。

  1. DMAバッファの構築: 16ビットの各ビット値（0または1）に対応するタイマーの比較一致レジスタ（CCR）の値を、16要素の配列（uint32_t または uint16_t）としてメモリ上に用意します。
  2. タイマー設定: PWMモードに設定し、タイマー周期（ARR）をDShot600の1ビット期間（1.667µs、例えば 168MHz駆動なら ARR=280）に固定します。
  3. DMA転送トリガー: PIDループのパケット送信タイミングで、タイマーのアップデートイベント（UDE）または比較一致イベントをトリガーに、DMAでCCRレジスタへバッファからデータを次々に自動転送（バースト転送）させます。

5. 双方向DShot（Bidirectional DShot）の拡張

現代のファームウェア（Betaflight / Bluejay 等）で必須となる双方向DShotでは、物理層の結線（1線のみ）をそのままに、ハーフデュプレックス（半二重）通信を行います。

  1. FCからESCへの送信: FCが通常通り16ビットのDShotフレームを送信（約26.7µs）。
  2. バスの反転: FCはピンを出力（Output）からプルアップ付き入力（Input Filtered）へ切り替えます。
  3. ESCからFCへの返送: 命令を受け取ったESCは、即座に自身のタイマーを用いて、モーターの最新のエルゴ（eRPM: 電気的回転数）データを12ビットのパケット（+4ビットCRC）にエンコードし、同じ信号線を使ってFCへ逆方向にバースト送信します。
  4. FCでの受信: FCのタイマーのインプットキャプチャ（IC）機能とDMAを組み合わせ、パルス幅を計測してeRPMを復調します。これをベースにRPMノッチフィルターを駆動させます。

※設計上の注意点として、DShot600は高速なため、基板の浮遊容量やインダクタンスによる信号波形のなまりを防ぐ目的で、FC-ESC間の信号線には通常 10Ω〜100Ω 程度のダンピング抵抗を直列に挿入し、インピーダンス整合と反射ノイズの抑制を行うのが一般的です。
