プロポ側の処理とデータ算出メカニズム

1. プロポ内部での処理の流れ

プロポの内部では、スティックの動きが以下の4つのステップで処理され、ドローン（ESP32-C6）へ電波で送信されます。

[スティックの物理的傾き] ↓ ① ADC（電圧の読み取り） ↓ ② キャリブレーション（0 ～ 100%への正規化） ↓ ③ EXPO / デッドバンド処理（操縦性の味付け） ↓ ④ パケット化（SBUS、CRSF、PWMなどの通信データへ変換）

2. 操作子データからプロポ入力への変換ステップ

具体的にマイコン（プロポ側）でどのような計算が行われているか、ステップ順に解説します。

① ADCによるデジタル値化

スティックの根元には「ポテンショメータ（可変抵抗）」や「ホールエフェクトセンサー（磁気センサー）」がついており、スティックの傾きに応じて電圧が変わります。プロポ内のマイコンがこれをADC（アナログ・デジタル変換）で読み取ります。

  • 例：12bit ADCの場合、値は 0 ～ 4095（センターは 2048 付近）になります。

② キャリブレーションと正規化

センサーの個体差やズレを補正し、扱いやすいように -1.0 ～ +1.0（または 0 ～ 100%）の範囲に正規化 します。

  • スティック最左 (最小値): In_min = 200
  • スティック中央 (中立値): In_center = 2020
  • スティック最右 (最大値): In_max = 3900

この実測値をもとに、現在値（raw_adc）を -1.0 ～ 1.0 の変数 stick_input にマッピングします。

// センターより左（下）にある場合
if (raw_adc < In_center) {
    stick_input = (float)(raw_adc - In_center) / (In_center - In_min);
} 
// センターより右（上）にある場合
else {
    stick_input = (float)(raw_adc - In_center) / (In_max - In_center);
}
stick_input = constrain(stick_input, -1.0, 1.0); // 念のため限界値をクリップ

③ デッドバンド（遊び）と EXPO（エキスポ）処理

正規化した stick_input をそのままドローンに送ると、スティックのわずかな震えでドローンがブレたり、中心付近の操作が敏感すぎてホバリングが難しくなったりします。そのため、以下の2つの処理（味付け）を行います。

  • デッドバンド（Deadband）： スティックの中心付近（例：±3%）を強制的に 0 にする「遊び」を設けます。これにより、指を離したときの微妙なズレを無視できます。
  • EXPO（Exponential：指数カーブ）： 直線のグラフではなく、3次曲線（カーブ）に変形させます。これを行うことで、「スティック中心付近では動きがマイルド（ホバリングしやすい）」になり、「大きく倒したときだけ急激に大きく動く（アクロバット飛行ができる）」という理想的な操縦性になります。

【数式によるEXPOの計算例】

EXPOの度合いを 0.0（直線）～ 1.0（強いカーブ） の間で調整できるようにする一般的な数式です。

float expo = 0.4; // EXPOの強さ（40%）
// 3次関数を使ってカーブを作る
float stick_expo = (1.0 - expo) * stick_input + expo * (stick_input * stick_input * stick_input);

④ 最終的な目標値への変換（スケーリング）

最後に、この -1.0 ～ 1.0 に変形された値を、ドローンが理解できる「目標角度」や「目標角速度」に変換します。

  • アングルモード（自動水平：初心者向け）の場合： スティック最大傾きを「最大45度（ラジアン換算：約0.785）」に設定したい場合：
    目標角度 (cmd_angle) = stick_expo × 45.0 × (π / 180.0)
  • アクロモード（手動制御：上級者・レース向け）の場合： スティック最大傾きを「秒間700度（700 deg/s）の回転」に設定したい場合：
    目標角速度 (target_rate) = stick_expo × 700.0

3. ドローン（受信側）はどうやって受け取る？

プロポ側で計算されたこれらのデータは、最終的に通信プロトコル（CRSFやSBUS、またはESP-NOWなど）に乗せるために、一般的には 1000 ～ 2000 （センターが 1500）というマイクロ秒（μs）単位のデジタル数値（チャンネルデータ）に変換されて電波で飛びます。

ドローン側（ESP32-C6）の受信機は、この 1000?2000 という数値を読み取り、それを再び逆算して「あ、今プロポは右に15度傾けろと言っているな」と判断して、クォータニオン制御コードの cmd_roll などに代入します。
