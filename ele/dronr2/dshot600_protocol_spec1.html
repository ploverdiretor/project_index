DShot600 プロトコル仕様書

本ドキュメントは、フライトコントローラー（FC）およびESC（Electronic Speed Controller）におけるDShot600プロトコルのファームウェア実装およびハードウェア設計のためのテクニカルリファレンスです。

1. 物理層と信号符号化（Encoding）

DShotは、1ビットのパルス幅（デューティ比）によって「0」と「1」を表現するPWMパルス幅符号化（TDR: Time-Domain Representation）を採用しています。ビットレートは 600 kbps です。

■ タイムスロット構造 (T = 1.667 µs)

  • ビット「0」: 周期の 37.5% の期間 HIGH、残り 62.5% は LOW
  • ビット「1」: 周期の 75.0% の期間 HIGH、残り 25.0% は LOW
ビット「0」の波形:
|-- 625ns --|----------- 1042ns -----------|
[===========]______________________________| (計 1,667ns)

ビット「1」の波形:
|----------- 1250ns -----------|-- 417ns --|
[==============================]___________| (計 1,667ns)

■ タイミング規定表

パラメータ 理論値（DShot600） 計算式
1ビット総時間 (T) 1,667 ns 1 / 600,000 秒
「0」のHIGH時間 (T₀H) 625 ns T × 0.375
「1」のHIGH時間 (T₁H) 1,250 ns T × 0.750

2. フレーム構造（Frame Structure）

1フレームは 16ビットの固定長 で構成され、MSB（最上位ビット）から順に送信されます。

MSB                                                        LSB
+-------------------------------------+-----------+----------+
|       Throttle Value (11-bit)       | Telemetry |   CRC    |
|              [15 : 5]               |   (1-bit) | (4-bit)  |
+-------------------------------------+-----------+----------+
  • Throttle Value (11bit / Bit 15-5): 0～2047 の値。
    • 0: ディスアーム（停止状態）
    • 1～47: コマンドモード（ビーコン鳴動、回転方向反転など）
    • 48～2047: スロットル出力（48が最小、2047が最大出力）
  • Telemetry (1bit / Bit 4): 1 の場合、ESCに対してテレメトリデータの返送を要求。
  • CRC (4bit / Bit 3-0): 上位12ビット（Throttle + Telemetry）を4ビットずつに3分割したXORチェックサム。

■ CRC計算アルゴリズム (C言語実装例)

/**
 * @brief DShotの16bitフレームを構築し、CRCを計算・付与する
 * @param throttle 11ビットのスロットル値 (0 - 2047)
 * @param telemetry 1ビットのテレメトリ要求フラグ (0または1)
 * @return 構築された16ビットのDShotパケット
 */
uint16_t prepare_dshot_packet(uint16_t throttle, uint8_t telemetry) {
    // 上位12ビットのデータを作成
    uint16_t packet = (throttle & 0x07FF) << 1;
    packet |= (telemetry & 0x01);

    // 4ビットずつのXORによるCRC計算
    uint8_t crc = (packet ^ (packet >> 4) ^ (packet >> 8)) & 0x0F;

    // パケットを4ビット左シフトし、下位にCRCを結合
    return (packet << 4) | crc;
}

3. マイコン（MCU）実装戦略とDMA制御

CPUの負荷を最小化するため、一般的にはDMA（Direct Memory Access）付きのタイマー（TIM）を使用して波形を自動生成します。

■ 送信バッファの仕組み

1フレーム（16ビット）を送信するために、タイマーの比較一致レジスタ（CCR）に流し込む 16要素の配列 をメモリ上に展開します。各要素には、ビットが0か1かに応じたCCRの設定値を格納します。

■ インターフレームギャップ

ESC側がフレームの終端を検出し、カウンタをリセットするために、フレーム間には必ず 最小30 µs以上 の LOW 期間（リセットタイム）を設ける必要があります。

■ STM32（HALレイヤ）を想定した送信擬似コード

// 16ビットデータ + リセット期間用のダミー要素
uint32_t dshot_dma_buffer[16 + 1]; 

void update_dshot_buffer(uint16_t packet) {
    for (int i = 0; i < 16; i++) {
        // MSBから評価
        if (packet & (1 << (15 - i))) {
            dshot_dma_buffer[i] = TIM_CCR_VAL_BIT_1; // 75% デューティ値
        } else {
            dshot_dma_buffer[i] = TIM_CCR_VAL_BIT_0; // 37.5% デューティ値
        }
    }
    dshot_dma_buffer[16] = 0; // リセットタイム用 (LOW固定)
}

void send_dshot_frame(void) {
    // タイマーのDMA転送を開始
    HAL_TIM_PWM_Start_DMA(&htim1, TIM_CHANNEL_1, dshot_dma_buffer, 17);
}

4. 双方向DShot（Bidirectional DShot）への拡張

双方向DShotでは、同一の1線を用いて半二重（ハーフデュプレックス）通信を行います。FCがフレームを送信し終えた直後、信号線の方向を反転させてESCからのERPM（電気的回転数）データを受信します。

【双方向DShotのタイムラインシーケンス】
|<- FC送信: DShotフレーム (16bit) ->| ターンアラウンド |<- ESC返送: ERPMデータ (16bit) ->| リセット |
|------------- 26.67 µs -------------|~~~ 2～5 µs ~~~|------------- 26.67 µs ------------|--- >30µs --|

ESCから返送されるERPMデータも同様に16ビット（12ビットの回転数データ + 4ビットのCRC）のPWM符号化で返されるため、FC側はタイマーのインプットキャプチャ機能（両エッジ検出）とDMAを組み合わせ、パルス幅の計測（復調）をハードウェア単体で処理します。

ハードウェア設計上の注意点:
DShot600は立ち上がりエッジが非常に急峻なため、浮遊容量による信号の反射やオーバーシュートが問題になるケースがあります。FCの出力ピンとESCの入力ピンの間には、インピーダンス整合とノイズ抑制のために必ず 10Ω～100Ω のダンピング抵抗 を直列に挿入してください。
